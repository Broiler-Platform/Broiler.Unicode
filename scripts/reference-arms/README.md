# Bundle sjl-7-001's reference arms: the population, the arbiter and the classification

**What this directory is.** The Python half of the library-level reference-arm comparison that
[`docs/evidence/sjl-7-001/reference-arms.md`](../../docs/evidence/sjl-7-001/reference-arms.md) declares (the rule;
it is normative, and nothing here revises it): the generator of its population (classes U1 to U7), the
independent reference computation it names as the arbiter, and the owner's classification of the comparison's
differences. The comparison itself, which runs S and the arms V and J over the population and lists every
difference, is C# and lives in this repository's test project; it classifies nothing.

It follows the shape of Broiler.JS's earlier reference-arm scripts (`scripts/conformance/` in that repository:
`generate_text_population.py`, `generate_date_population.py`, `textref.py`, `classify_text_arms.py`,
`classify_date_arms.py`), and reuses their SplitMix64 and their reading of a draw.

## Files

| File | Committed | What it is |
|---|---|---|
| `splitmix64.py` | yes | SplitMix64, copied unchanged from Broiler.JS, and the four readings of a draw |
| `generate_population.py` | yes | the population's generator (U1 to U7) |
| `unicoderef.py` | yes | the arbiter: Unicode's algorithms written from the standards, reading only the pinned files |
| `classify_reference_arms.py` | yes | the owner's classification of the comparison's differences, written before the judged run |
| `cells.json` | yes | the correspondence's run cells of rows C1-C11, N1-N7, S1-S3 and G1-G7, with their source lines |
| `tests/` | yes | the unit tests (`python3 -m unittest discover -s scripts/reference-arms/tests`) |
| `.gitignore` | yes | `__pycache__/` |
| the population, the arbiter's outputs, the classification | **no** | written outside the repository or under `artifacts/` (git-ignored); regenerated byte for byte from the commit and the pin |

## Commands

From the repository root:

```sh
# 1. The population (about 10 s). --out is required; inside the repository only artifacts/ is accepted.
python3 -I scripts/reference-arms/generate_population.py --out artifacts/reference-arms/population

# 2. The arbiter's answer for every input of every population file (about 15 s with 4 jobs, 36 s with 1).
python3 -I scripts/reference-arms/unicoderef.py --population artifacts/reference-arms/population \
    --out artifacts/reference-arms/reference [--jobs N]

# 3. After the comparison has written <run>/differences.tsv.gz: the classification, cross-checked against the
#    arbiter's recorded answers of step 2.
python3 -I scripts/reference-arms/classify_reference_arms.py --run <run> \
    --reference artifacts/reference-arms/reference [--examples 20]

# The tests (about 30 s).
python3 -m unittest discover -s scripts/reference-arms/tests
```

`-I` is not needed for these trusted files, and harmless: each script puts its own directory on `sys.path`.
`--pins <unicode.pin>` points any of the three at another copy of the pin (the tests use it for the negative
controls); the default is this repository's `data/unicode/pins/unicode.pin`.

**The pin.** Every Unicode or ECMA-262 file any script reads is one `data/unicode/pins/unicode.pin` names, and is
read only after its length and SHA-256 match the pin's line. A mismatch, a missing file or a file no line names
is refused: the generator and the arbiter print `refused: ...` and exit 2 before writing anything (tests:
`RefusalTests`, a changed byte of `CaseFolding.txt` and a changed hash of `SpecialCasing.txt`'s pin line). The
manifests record the pin's SHA-256 and the SHA-256 of every pinned file read. No script reads `src/` or any
generated table, and none imports Python's `unicodedata`.

## The draw, and the seeds

**SplitMix64** is Broiler.JS's `splitmix64` (`scripts/conformance/generate_number_vectors.py`, git blob
`446eabb54d4e6dd19cfa6963d2a19440eea4d694` at Broiler.JS `3916bd2b`), copied unchanged: Vigna's
`splitmix64.c`, state advanced by `0x9E3779B97F4A7C15`, mixed by `(z ^ (z >> 30)) * 0xBF58476D1CE4E5B9`,
`(z ^ (z >> 27)) * 0x94D049BB133111EB`, output `z ^ (z >> 31)`, all modulo 2^64.
`tests/test_splitmix64.py` checks the published reference outputs: seed 1234567 gives 6457827717110365317,
3203168211198807973, 9817491932198370423, 4593380528125082431, 16408922859458223821, as Broiler.JS's
`tests/test_reference_population.py` checks them; seed 0 gives `0xE220A8397B1DCDAF`.

**A draw is one output of SplitMix64 from the class's seed, consumed in the order the generator states, and it
is read in exactly one of four ways:** a choice among n things is the draw modulo n; an integer from
[low, high] is low plus the draw modulo (high - low + 1); a second value from the same draw is the draw shifted
right by 16 bits, modulo its own range; a third value from the same draw is the draw shifted right by 32 bits,
modulo its own range.

| Class | Seed | Draws |
|---|---|---|
| U2 | `0x534A4C372D303031` ("SJL7-001") | 2^14 strings |
| U3 | `0x534A4C372D303032` ("SJL7-002") | 2^16 strings |
| U4 | `0x534A4C372D303033` ("SJL7-003") | 2^16 strings |
| U6 | `0x534A4C372D303034` ("SJL7-004") | 2^16 strings |

## The population

The generator writes six files and `manifest.json` into `--out`. Every file is UTF-8 with LF line endings and a
final LF. **Determinism:** the same pinned files give the same bytes; two full runs in two processes with
different `PYTHONHASHSEED` were compared byte for byte (and `DeterminismTests` does the same on `--reduced`).
`--reduced` writes a small population for the tests (draws divided by 256, a few hundred code points) and marks
its manifest `"size": "reduced"`; it is never the judged one.

### Text files

`casing.tsv`, `normalization.tsv`, `string-properties.tsv` and `segmentation.tsv`: one input per line,

```
<UTF-16 code units, 4-digit upper-case hexadecimal, separated by single spaces>\t<tag>
```

e.g. `0041 D800 0027 03A3\tsurrogate:inside1:D800:AcΣ`. Code units, not code points, so a lone surrogate is
unambiguous: a high surrogate unit followed by a low one is a pair, any other surrogate is lone. Where the
generator places a lone surrogate (U3's contexts, the cells) it is inserted at a code-point boundary and never
pairs; where it draws surrogates (U4, U6), a drawn high one followed by a drawn low one is a pair, as in any
string. The tag names the sub-class the line comes from; tags may hold non-ASCII
characters (the contexts) and never a tab. The harness runs each casing line in the three languages (default,
Turkic, Lithuanian) and both directions, each normalization line in the four forms and each segmentation line at
the three granularities; no line is repeated for that.

### `names.tsv` (U2)

```
<kind>\t<property>\t<value>
```

kind `lone` (the name is the property field and the value field is empty, so the line ends with a tab) or
`pair` (Name=Value). Fields are never trimmed, and no name holds a tab, a newline or a `/`. The file has no tag
column; its sub-classes follow one another in this order, and `manifest.json` (`classes.U2.subclasses`) records
each one's first line and count. A line of the deterministic sub-classes is written once, the first time; the
drawn lines are written as drawn.

| Sub-class | Lines | What |
|---|---|---|
| `ecma262` | 111 | every name and alias of ECMA-262's three tables (parsed from the archived HTML), alone: the 98 binary names and aliases, the 7 properties of strings, and the 6 non-binary names (refused alone) |
| `property-aliases` | 177 | every name and alias of PropertyAliases.txt, alone: Age, Block, Name, Bidi_Class, Line_Break and every other UCD property outside the tables among them |
| `value-aliases` | 1,388 | every value and alias of PropertyValueAliases.txt, every property, alone |
| `pairs` | 1,544 | General_Category, gc × every gc value alias; Script, sc and Script_Extensions, scx × every sc value alias |
| `refused-case` | 5,492 | each admitted name (lone: the binary aliases, the gc value aliases, the properties of strings; pair: each value of its property under each alias of the property, and each property alias with `Lu`/`Uppercase_Letter` or `Latn`/`Latin`) lower-cased, upper-cased, case-swapped and with its first letter swapped |
| `refused-underscore` | 404 | the same names with one underscore removed, each in turn |
| `refused-space-hyphen` | 27,586 | the same names with a space or a hyphen inserted at every position, both ends included, and with each underscore replaced by a space or a hyphen |
| `refused-is` | 1,741 | the same names with an `Is` prefix |
| `refused-wrong-property` | 2,516 | gc values as values of sc/scx, sc values as values of gc, binary names, properties of strings and property names as values of gc/sc/scx, and binary properties and properties of strings given each Y/N value |
| `outside-tables` | 2,878 | every other property of PropertyValueAliases.txt as Name=Value, every alias on both sides (Age=1.1, Block=Basic_Latin, bc=L, lb=AL, ccc=230, Alpha=Yes...) |
| `cells` | 1 | the names of rows S1 and S2 not already present (`rgiemoji`) |
| `random` | 32,768 | 2^14 drawn strings, each written twice |

A mutation that happens to be an admitted name for its slot is left out (it is not in the refused set). Only
admitted names are mutated: every other name is refused already.

**The drawn strings.** The alphabet is the sorted set of the characters of every property and value field of
the deterministic sub-classes: ` -.0123456789A-Za-z_` (66 characters, the manifest records it). For each of the
2^14 strings, in order: one draw gives the length, an integer from [1, 40]; one draw per character chooses it
from the alphabet; one draw gives the split, an integer from [0, length]. The string is then written as
`lone\t<string>\t`, and immediately after as `pair\t<string[:split]>\t<string[split:]>` (either side may be
empty).

### `casing.tsv` (U3)

| Tag | Lines | What |
|---|---|---|
| `alone` | 1,114,112 | every code point U+0000 to U+10FFFF alone, a surrogate as one unit (written, as the brief asks) |
| `context:<template>` | 78,738 | for each of the 7,158 code points c that are Cased, Case_Ignorable or Soft_Dotted, or are I, J, Į, Σ, İ or ı, each of the rule's eleven contexts with c substituted: `AcΣ`, `AΣc`, `cΣ`, `Σc`, c U+0307, c U+0301 U+0307, c U+0903 U+0307, `Ic`, `Jc` U+0300, c U+0345, `cA` (the tag holds the template as the rule writes it, the letter c and the marks themselves) |
| `surrogate:<where>:<unit>:<template>` | 544,008 | each context with U+D800 and with U+DC00 inserted at each code-point boundary: `before` (position 0), `after` (the end) and `inside1`, `inside2` (between code points); inserted at a boundary, a lone unit never pairs |
| `cell:<row>` | 30 | the run cells of C1-C11 (cells.json), one line per distinct text of a row |
| `random` | 65,536 | 2^16 drawn strings |

**The drawn strings of U3.** For each string: one draw gives the count, an integer from [1, 12]; then one draw
per code point: the choice among the 16 kinds `context` ×4, `ascii` ×4, `mark0`, `mark220`, `mark230` ×2,
`mark-other`, `special` ×3 is the draw modulo 16, and the code point is the kind's pool at the second value
(draw >> 16, modulo the pool's size). Pools, each in code point order: `context`, the 7,158 code points above;
`ascii`, U+0000 to U+007F; `mark0`, the marks (gc Mn, Mc, Me) of combining class 0; `mark220`, `mark230`, every
code point of class 220 and 230; `mark-other`, every code point of any other non-zero class; `special`, I, J, Į,
Σ, İ, ı, i, j, U+0307, U+0300, U+0301, U+0345, U+0903 and A.

### `normalization.tsv` (U4)

| Tag | Lines | What |
|---|---|---|
| `alone` | 1,114,112 | every code point alone |
| `test-file:NormalizationTest.txt:<line>:c<k>` | 100,170 | every column c1 to c5 of every line of every part (0 to 5) |
| `cell:<row>` | 19 | the run cells of N1, N2, N4 and N5 (N3, N6 and N7 have none) |
| `random` | 65,536 | 2^16 drawn strings |

**The drawn strings of U4.** One draw gives the count, from [1, 12]; one draw per code point chooses among the
16 kinds `starter` ×3, `mark` ×3, `L`, `V`, `T`, `LV`, `LVT`, `exclusion`, `singleton`, `non-starter`,
`supplementary`, `surrogate` (draw modulo 16); for `mark` the second value chooses the combining class among
every non-zero class in increasing order and the third value (draw >> 32) the code point of that class; for
every other kind the second value chooses the code point. Pools: `starter`, the starters that begin a
two-code-point canonical decomposition, and A-Z, a-z; `L`, `V`, `T`, the conjoining jamo (T from U+11A8);
`LV`, `LVT`, the syllables; `exclusion`, Full_Composition_Exclusion; `singleton`, the one-code-point canonical
decompositions; `non-starter`, a canonical decomposition of or starting with a non-starter; `supplementary`, a
code point above U+FFFF with a decomposition or in a composition pair; `surrogate`, U+D800 to U+DFFF. A drawn
high surrogate followed by a drawn low surrogate forms a pair, as in any string.

### `segmentation.tsv` (U6)

| Tag | Lines | What |
|---|---|---|
| `test-file:<file>:<line>` | 766 + 1,944 + 512 | the text of every line of GraphemeBreakTest.txt, WordBreakTest.txt and SentenceBreakTest.txt (the harness runs each at all three granularities) |
| `cell:<row>` | 10 | the run cells of G1-G3 |
| `random` | 65,536 | 2^16 drawn strings |

**The drawn strings of U6.** One draw gives the count, from [1, 16]; one draw per code point chooses a kind
(draw modulo the number of kinds) and the code point within it (the second value). The kinds are every value of
Grapheme_Cluster_Break, Word_Break and Sentence_Break that has a code point (48, weight 1 each: the rule's
"uniform choice of the values", each value's pool its code points in order, the surrogates in the Other pools),
followed by six extra kinds that carry the rule's "spaces, punctuation, digits, ideographs, Katakana and regional
indicators weighted as their test files weigh them": `space` (Sentence_Break Sp), `punctuation` (gc P*),
`digit` (gc Nd), `ideograph` (Ideographic), `katakana` (Word_Break Katakana), `regional-indicator`. A kind's
weight w is its share of the code points of the three test files' lines times 48, rounded half up, at least 1, and
the kind is listed w times: 2, 11, 4, 1, 1, 1 (68 kinds; the manifest records them).

### `limits.tsv` (U7)

Two kinds of line:

```
<UTF-16 code units>\t<family>:<what>
repeat\t<piece: code units>\t<count>\t<suffix: code units, possibly empty>\t<family>:<what>
```

A `repeat` line is the text `piece` repeated `count` times, then `suffix`; the harness builds it. The family is
`casing` (run in the six casing operations) or `normalization` (the four forms). The declared set:

- casing: every code point whose full mapping alone, in some language, changes its length in code units (106
  lines); contexts that lengthen (Lithuanian I U+0300, J U+0301, Į U+0301, Ì) and shorten (Lithuanian i U+0307,
  j U+0307 U+0301; Turkic I U+0307, I U+0316 U+0307) the text, and `AΣ`;
- normalization: inputs whose forms are longer (é, U+0344, U+0F73, U+1D15E, U+FB01, U+FDFA, U+3300, U+2474,
  U+AC01) and shorter (e U+0301, a Hangul L V T, U+1D400, U+2F800, A U+030A);
- results of 2^24 code units and one more, as `repeat` lines: casing `ß`×2^23 (upper), `İ`×2^23 (lower),
  `ΐ`×5,592,405 + `a` or `aa` (upper), `Ì`×5,592,405 + `a` or `aa` (Lithuanian lower), `a`×2^24 (+ `a`);
  normalization `é`×2^23 (NFD; with `a` also row N6's case, an NFC result of 2^23 + 1 whose decomposition is
  2^24 + 1), e U+0301 ×2^23 (+ `a`), U+FDFA×932,067 + 10 or 11 `a` (NFKD), U+1D15E×2^22 (+ `a`), `a`×2^24 (+ `a`).
  Each line's tag names the operation it reaches 2^24 or 2^24 + 1 in; `tests/test_population.py` checks it.

**The maximum-length variants** of every U3 and U4 input (the rule's "each input of U3 and U4 run with no limit
and with a maximum result length of the result's length, one less and one more") are the harness's: it is not
written. The arbiter's answer under a maximum m is the result when its length is at most m and `over` otherwise;
so under the result's length L the result, under L - 1 `over`, under L + 1 the result.

### `manifest.json`

`rule`, `generator`, `generator_version` (`sjl-7-001-population@1`), `reference`, `size`, `pin` (path, SHA-256,
version), `inputs` (the SHA-256 of every pinned file read), `cells` (cells.json's SHA-256), `draw` (the rule
above), `seeds`, and `classes`: `U1` with no file (`"implicit"`, count 1,114,112), and for U2 to U7 the `file`,
its `lines`, its `sha256` (of the file's bytes), `tags` (counts per tag, a tag's line numbers removed, so
`test-file:WordBreakTest.txt:123` counts under `test-file:WordBreakTest.txt`), and the class's own fields (seed,
draws, kinds, alphabet, sub-classes).

## `cells.json`

The run cells, transcribed from Broiler.VM's `docs/evidence/sjl-7-001/correspondence.md` (read at `7b44dc7`, git
blob `16bcad4f...`, its SHA-256 recorded in the file). Each cell: `row`, `line` (1-based, the row's table line),
`quote` (the input exactly as the line writes it; each was checked to occur verbatim in that line), `family`
(the population file it goes into), `units` (the text as code units: authoritative), `operation` and `parameter`
(what the row ran, informative: the harness runs every operation of the family), and a `note` where the row
leaves something open. Choices made here, each noted in the cell: N4's "Hangul both ways" is U+D4DB and its jamo
U+1111 U+1171 U+11B6 (UAX #15's example); G3's "a Hangul syllable sequence" is 한글 precomposed (U+D55C U+AE00)
and as conjoining jamo. C9's `('x!')` and N5's `'nfc'` are refused by the adapters before any library call; their
texts are still run. `rows_without_run_cells` lists C12, C13, N3, N6, N7, S3, G4-G7 and why.

## The arbiter: `unicoderef.py`

Written from the standards, reading only the pinned files (see its docstring): General_Category from
UnicodeData.txt (the groups from PropertyValueAliases.txt's own `#` comments; checked equal to
DerivedGeneralCategory.txt), every binary property of ECMA-262's table from PropList.txt,
DerivedCoreProperties.txt, DerivedNormalizationProps.txt, DerivedBinaryProperties.txt and emoji-data.txt (Any,
ASCII, Assigned as UTS #18 defines them), Script and Script_Extensions per UAX #24 (Unknown by default; a code
point ScriptExtensions.txt does not list takes its Script); ECMA-262's exact lookups; simple folding and orbits
(CaseFolding.txt C and S); Canonicalize without u (22.2.2.7.3); full case mapping per section 3.13 with
SpecialCasing.txt's conditions in the default, Turkic (tr, az) and Lithuanian (lt) languages; UAX #15's four forms;
the seven properties of strings; UAX #29's three segmentations.

Points where the text needed reading, each tested:

- **Final_Sigma is possessive.** Section 3.13.1 (checked in the Unicode 16.0 core specification's text): "The
  regular-expression operator * in Table 3-17 is "possessive," consuming as many characters as possible, with no
  backup", because Cased and Case_Ignorable overlap (U+0345, U+02B0...); a character in both is consumed as
  case-ignorable. So `ΑΣʰ` lowers to `ας` ʰ, as correspondence row C2 reports for both engines, and the
  standard's own U+0345 examples are tests.
- **Script_Extensions uses Script's values** (PropertyValueAliases.txt says so; it lists no scx line), and Hrkt
  resolves to an empty set (row P2).
- **A lone surrogate** is a code point of its own: no case mapping, not Cased, not Case_Ignorable, class 0, no
  decomposition, never composing; in segmentation it has the files' `@missing` values (Other for all three).
- **ID_Start and ID_Continue with Pattern_Syntax subtracted** are computed as the subtraction; in 17.0 it changes
  nothing (tested), since UAX #31 already subtracts it.

### Outputs (`--out`)

Each population file gets an answer file, line for line, in the population's order:

| File | Line |
|---|---|
| `names-ref.tsv` | `<kind>\t<property>\t<value>\t<resolution without v>\t<resolution with v>` |
| `casing-ref.tsv` | `<input>\t<upper default>\t<lower default>\t<upper turkic>\t<lower turkic>\t<upper lithuanian>\t<lower lithuanian>` |
| `normalization-ref.tsv` | `<input>\t<NFC>\t<NFD>\t<NFKC>\t<NFKD>` |
| `string-properties-ref.tsv` | `<input>\t<the properties holding it, comma-separated in ECMA-262's table order, or ->` |
| `segmentation-ref.tsv` | `<input>\t<grapheme boundaries>\t<word boundaries>\t<sentence boundaries>\t<word status>` |
| `limits-ref.tsv` | `<family>\t<result>...`, the six casing results in casing-ref's order or the four forms in normalization-ref's; a `repeat` line's results as `len:<code units>:sha256:<SHA-256 of the UTF-16LE bytes>` |

Texts are code units as in the population (an empty result would be an empty field); boundaries are positions in
UTF-16 code units, 0 and the length included, separated by single spaces. A resolution is `refused`, a binary
property's canonical name (`Alphabetic`), `<Property>=<Value>` with both long names
(`General_Category=Uppercase_Letter`, `Script=Latin`, `Script_Extensions=Katakana_Or_Hiragana`), or a property of
strings' name (`RGI_Emoji`, only with v). **The word status** is informative only: Y or N per word segment, Y when
the segment holds a code point of Word_Break ALetter, Hebrew_Letter, Numeric or Katakana, or one that is
Ideographic or of Script Hiragana (Broiler.VM's rule as row G4 reads it); the specification leaves it to the
implementation, so it arbitrates nothing (class (b), G4).

For class U1, the code-point operations' answers as sets and maps rather than a line per code point:

| File | Line |
|---|---|
| `sets.tsv` | `<name>\t<ranges>`: every set a lookup answers, named by its resolution (all gc values and groups, the 53 binary properties, every Script and Script_Extensions value), each property of strings' single code points, and `lexical:ID_Start-Pattern_Syntax`, `lexical:ID_Continue-Pattern_Syntax`, `lexical:IdentifierStartChar`, `lexical:IdentifierPartChar`, `lexical:RegExpIdentifierStart`, `lexical:RegExpIdentifierPart`, `lexical:WhiteSpace` (ECMA-262's production), `lexical:LineTerminator` |
| `string-sets.tsv` | `<property>\t<member>`: every member string of each property of strings |
| `folding.tsv` | `<code point>\t<simple folding>` where they differ |
| `orbits.tsv` | each orbit of more than one code point, its members in order |
| `canonicalize.tsv` | `<unit>\t<Canonicalize without u>` where they differ |
| `reference-manifest.json` | each output's line count and SHA-256, the pin's and each input's SHA-256, the population manifest's SHA-256, the seconds each step took |

Ranges are UCD notation separated by single spaces (`0041..005A 00B5`); the empty set is `-`. Every code point,
unit or text not listed in a map maps to itself.

The giant `repeat` results are computed exactly without building every intermediate list: casing, when every
code point of the piece and suffix has class 0 and is not Case_Ignorable, decides each mapping by its neighbours
alone (every condition's scan stops at the first character it reads), so the result is read off
`piece × 3 + suffix`; normalization, when the form has a boundary before the piece's and the suffix's first code
point, is the piece's normal form `count` times and the suffix's. Otherwise the whole text is built.
`tests/test_population.py` compares the shortcut with the full computation for every `repeat` line at counts 3, 4,
7 and 300.

### `differences.tsv`: the notation the classifier reads

The comparison writes `differences.tsv.gz`, one difference per line, optionally after a header starting
`operation\t`:

```
<operation>\t<class>\t<input>\t<parameter>\t<arm>\t<S result>\t<arm result>
```

`unicoderef.answer(ucd, operation, input, parameter)` gives the arbiter's answer in the same notation:

| Operation | Input | Parameter | Result |
|---|---|---|---|
| `binary` | a code point in hex (`0041`; `U+` accepted) | a binary name or alias | `true` / `false` |
| `gc`, `sc`, `scx` | a code point | `-` | the short value (`Lu`, `Latn`); scx: the short values sorted, space-separated |
| `lexical` | a code point | a `lexical:` set name without the prefix, `White_Space` or `Soft_Dotted` | `true` / `false` |
| `lookup` | `<kind>/<property>/<value>` (`lone/Lu/`, `pair/sc/Grek`) | `u` or `v` | a resolution, as above |
| `fold`, `canonicalize` | a code point / a code unit | `-` | hex |
| `orbit` | a code point | `-` | the orbit's code points, space-separated |
| `upper`, `lower` | a text, or `repeat:<piece>:<count>:<suffix>` | `default`, `turkic`, `lithuanian`, or a locale or a locale list (its first element decides: `tr,en`); optionally `@<host culture>` (ignored by the arbiter) and `;max=<n>` | a text, `over` (longer than the maximum), or `len:...:sha256:...` |
| `normalize` (or `NFC`...`NFKD`) | as above | the form, optionally `@...` and `;max=<n>` | as above |
| `string-property` | a text | a property of strings | `true` / `false` |
| `grapheme`, `word`, `sentence` | a text | `-` | boundary positions |
| `word-status` | a text | `-` | Y/N per word segment |
| `charge` | a text | the operation | an integer; no arbiter |

An arm's refusal is written `exception:<type>` or `error:<kind>` (and S's over-long status `over`); the classifier
reads any `exception`, `error`, `refused` or `over` result as a refusal.

## The classification: `classify_reference_arms.py`

Applied mechanically to `<run>/differences.tsv.gz`; **its predicates were written before the judged run** and,
like Broiler.JS's classifiers, any revision after a run has been seen is to be recorded as such. For each line:

1. an arm whose name contains `control` is a negative control: `unclassified`, never classified;
2. `charge`: class (c) always;
3. `word-status`: class (b), row G4;
4. the arbiter's answer; S's answer not the arbiter's: (c), a defect of S; both the arbiter's yet listed: (c);
5. S's answer the arbiter's and the arm's not: the arm's row predicates are tried in order; the first that holds
   gives the class and the row. None holding: **(c), flagged `unnamed`** (a correction the correspondence does
   not name falsifies JSD-0074, whatever the arbiter says).

The parameter conventions the predicates read (`,` for a locale list, `@<culture>` for arm J's second run under
tr-TR or lt-LT, `@invariant` for a run under invariant globalization, `;max=<n>`, an arm name holding `control`
for the negative controls) are part of the contract with the comparison.

**The arbiter's recorded answers.** The classifier computes each answer with `unicoderef.answer`. With
`--reference <unicoderef.py's --out>` it also reads, for the inputs the differences name, the answers recorded in
names-ref.tsv, casing-ref.tsv, normalization-ref.tsv, string-properties-ref.tsv and segmentation-ref.tsv, refuses a
reference written under another pin or arbiter version, and checks each recorded answer against the direct one;
one disagreement and nothing is written (exit 3). `classification.json` records how many were cross-checked. The
code-point operations and the `repeat` inputs, recorded as sets, maps and digests, are answered directly.

Outputs, in `<run>`: `classification.tsv.gz` (header; each difference's seven fields, the arbiter's answer, the
verdict, the row, the unnamed flag `yes`/`no`/`-`, the reason; a field longer than 256 characters shown as
`len:<characters>:sha256:<digest>`), `classification.json` (counts per verdict, per verdict/row/arm, per
operation/arm/verdict and per group, the unnamed count, and each listing's line count and SHA-256 of its
uncompressed text) and `report.md` (the counts and the first `--examples` lines of each group). The exit status is
0 when no difference is class (c), 1 otherwise, 2 when a pinned file is refused, 3 when a recorded answer is not
the arbiter's.

## Readings of the rule, and what differs from the brief

- **U3's "their Unicode 16 and 17 code points"**: no DerivedAge.txt is pinned, so the arbiter cannot select code
  points by age. Every code point alone is in U3, which holds them; C3's listed ones are also cells.
- **U5's "one added at either end"**: two code points are added, each at each end: U+200D and U+FE0F.
- **U5's single code points** are implicit (manifest), not written; U1 likewise.
- **U6's weighting** is read as six extra kinds weighted by the test files' shares (above); the rule's
  "uniform choice of the values" is kept for the 48 values.
- **The refused set** mutates admitted names only, and adds, beyond the rule's single changes, each underscore
  replaced by a space or a hyphen. Changes are single: a name changed twice (`rgiemoji`) is in only where a cell
  puts it.
- **NormalizationTest.txt** contributes all six parts (the decision rule's A1 names parts 0 to 3; every line
  passes either way).
- **The word status** has no arbiter; the arbiter's Y/N is informative.
- **The limits** are the harness's for U3 and U4; the arbiter answers any `;max=<n>`.
- **The classifier's row predicates** are mechanical readings of the correspondence's rows, not knowledge of the
  arms' code; where an arm writes a result in another notation than the table above, a predicate may not hold and
  the difference falls to (c), which the bundle would show.
